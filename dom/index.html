Simple Multithreaded Template

A ball you can roll around a floor: the smallest useful web app on three threads, and a template to start your own from.

Controls

W A S D or arrows roll the ball
Space put it back
R load the scene again
Stats, Settings what each thread is doing; resolution and anti-aliasing

How it works

Three threads share one block of memory. This page owns the canvas and the keyboard. A C app in a worker runs the game at a fixed 120 steps a second. A Rust WebGPU renderer (AwsmRenderer) in another worker draws it, blending between steps so motion stays smooth at any refresh rate. Nothing that happens every frame goes through postMessage.

Make it yours

Your game lives in three places: app/src/game/ (the logic, in C), dom/game.js (keys, HUD text, events) and media/ (the scene). Save a C file and the running page swaps the new build in, without a reload.

The README has the rest. Part of the Awsm project.

The Stats button (bottom left) opens a panel: a frame budget first, then one group per thread. Each group's header shows its main number; click a group to open its breakdown. A breakdown is only measured while its group is open, so the panel costs nothing when it is closed.

ms / frame is time per rendered frame. µs / step is time per simulation step (1000 µs = 1 ms). / s is per second.

frame budget

budget
The time one display refresh allows: 16.7 ms at 60 Hz, 8.3 ms at 120 Hz. It comes from your display's measured refresh rate.
headroom
The budget minus the largest lane below. The GPU and the threads work in parallel, so their times do not add up: each one has to fit the budget on its own. If it reads over by …, that lane cannot keep up with the display.
the lanes
One row for the GPU and one per thread: the time it uses per frame, out of the budget. Here: the GPU, the renderer, the app and the page.
latency (renderer + GPU), reference only
Roughly how long one frame takes from the renderer starting it to the GPU finishing it. Not what the budget is checked against.

Missed frames while there is headroom mean something is waiting rather than working, for example the CPU waiting on the GPU.

display

refresh rate
How often your display refreshes, as the browser paces this page.
frames presented
New frames shown per second (fps). Never more than the refresh rate.
missed frames
Refreshes that went by without a new frame. A steady count is visible stutter: lower the resolution or the anti-aliasing in Settings.

GPU

GPU time per frame
How long the GPU works on a frame, from timestamp queries. Reads n/a where the browser or the GPU does not offer them.
the rows
One per render pass. Some GPUs (Apple's) run passes overlapped, so the rows can add up to more than the frame.

renderer (render worker)

the header
The render thread's CPU time per frame.
read app state + interpolate
Reads the two latest simulation steps and blends between them for this frame's exact moment.
update transforms, set camera
Turns the new poses into world matrices, and sets the view.
render (encode + submit)
The renderer's own work, split into prepare (uploading this frame's data to the GPU), passes (encoding each render pass), submit (handing the frame to the GPU) and outside the scopes (the little that is left untimed). The smallest rows are folded into "N more under 1 µs".

app (C, app worker)

the header
CPU time of one fixed simulation step.
steps
Steps per second. Fixed (120), whatever the display does; the renderer blends between steps.
late frames
Frames drawn before the app had finished the moment they show; such a frame holds the previous pose. The row and the header turn red if it keeps happening.
read scene, read input, simulate, publish
The parts of a step, in order.

page (main thread)

app events + HUD
The page's own work per frame: the game's events and the HUD. It should stay tiny; the heavy work is in the workers.

Settings

Adjust these settings if your framerate is low.

Display Quality Reduced

Display quality was reduced to keep the frame rate up on touch devices. You can adjust the resolution and anti-aliasing any time in Settings (bottom right).

Compiling Pipelines

Rebuilding the render pipelines for the new anti-aliasing settings. The first switch in each direction compiles shaders; after that it's cached and instant.
